# Contributing to Content Creation Automation

Welcome to the team! To keep our development smooth and organized, please follow these guidelines.

## 🌿 Branching Strategy
- **main**: The stable production-ready code. No direct commits allowed.
- **feature/feature-name**: Use this for new features or tasks.
- **bugfix/bug-name**: Use this for fixing issues.

## 📝 Commit Messages
We follow a simplified version of [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` for new features (e.g., `feat: add /settings command`)
- `fix:` for bug fixes (e.g., `fix: resolve token overwrite bug`)
- `docs:` for documentation changes
- `chore:` for maintenance tasks (e.g., `chore: update docker-compose`)

## 🐍 Coding Standards
- Use **snake_case** for variables and functions.
- Use **PascalCase** for classes.
- Every function should have a brief docstring explaining its purpose.
- Keep functions focused on a single task.

## 🚀 Workflow
1. Create a branch from `main`.
2. Implement your task.
3. Test locally.
4. Push your branch and create a Pull Request (PR).
5. Assign **Sabih** for review.
